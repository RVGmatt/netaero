Modello Client-Server

Il Web si basa sull'architettura Client-Server: il Client (browser o app) avvia la comunicazione inviando una richiesta; il Server (host remoto sempre attivo in ascolto su una porta) elabora la richiesta e restituisce la risorsa o un messaggio di errore.

I Quattro Protocolli Applicativi

HTTP & DNS (obbligatori) + HTTPS/TLS & SMTP (sicurezza Web e posta elettronica)

Porta TCP 80 • Stateless • Request / Response

HTTP (HyperText Transfer Protocol)

È il protocollo alla base del Web. È stateless (senza stato): il server non conserva memoria delle richieste precedenti; per mantenere una sessione attiva (es. carrello o login) si usano meccanismi aggiuntivi come Cookie o Token.

Metodi HTTP Principali
GET

Recupera una risorsa (HTML, immagine, JSON) senza modificare lo stato del server.

POST

Invia dati nel corpo (body) della richiesta per creare o elaborare nuove risorse.

PUT

Sostituisce o aggiorna integralmente una risorsa già presente sul server.

DELETE

Richiede la rimozione della risorsa identificata dall'URL.

Codici di Stato (Status Codes)
200 OK 201 Created 301 Redirect 400 Bad Request 401/403 Auth Error 404 Not Found 500 Server Error

Porta UDP/TCP 53 • Sistema Gerarchico Distribuito

DNS (Domain Name System)

Traduce i nomi di dominio leggibili dall'uomo (es. www.esempio.it) negli indirizzi IP numerici usati dai router per instradare i pacchetti.

1. Cache & Resolver Ricorsivo: Controlla prima nella memoria locale (con tempo di validità TTL), poi interroga la gerarchia mondiale per conto del client.
2. Root (.) → TLD (.it/.com) → Autoritativo: La ricerca scende ad albero fino al server che custodisce la zona ufficiale del dominio.
Record DNS Fondamentali
A / AAAA

Associa il dominio a un indirizzo IPv4 (A) o IPv6 (AAAA).

CNAME

Alias canonico: reindirizza un nome di dominio verso un altro nome.

MX (Mail Exchange)

Specifica i server SMTP incaricati di ricevere le email per quel dominio.

Porta TCP 443 • Crittografia & Certificati X.509

HTTPS e TLS (Transport Layer Security)

Protegge le comunicazioni Web incapsulando HTTP dentro un canale cifrato TLS. Impedisce attacchi di intercettazione (sniffing) e alterazione dei dati (Man-in-the-Middle).

Riservatezza

Dati illeggibili a terzi grazie alla cifratura simmetrica.

Integrità

Codice MAC verifica che nessun bit sia stato modificato.

Autenticità

Certificato firmato da una CA garantisce l'identità del sito.

TLS 1.3 Handshake (Fasi Chiave)
1. ClientHello: Il browser invia versione TLS, cifrari supportati e parametri per lo scambio chiavi.
2. ServerHello + Certificato: Il server risponde e invia il certificato digitale con la propria chiave pubblica.
3. Chiave di Sessione: Entrambi derivano la stessa chiave simmetrica veloce per cifrare tutto il traffico HTTP successivo.
Porte TCP 25 / 587 / 465 • Posta in Uscita

SMTP (Simple Mail Transfer Protocol)

Governa la spedizione e l'inoltro delle email dal client al server di posta e tra server diversi tramite comandi testuali e codici numerici di risposta.

Confronto rapido con la ricezione: SMTP serve solo per inviare. Per leggere la posta ricevuta si usano IMAP (sincronizza le cartelle sul server su più dispositivi) oppure POP3 (scarica le email in locale).
Sequenza Comandi SMTP
EHLO Presentazione del client
MAIL FROM: Indirizzo mittente
RCPT TO: Indirizzo destinatario
DATA ... . Corpo messaggio chiuso da punto
QUIT Chiusura sessione TCP
